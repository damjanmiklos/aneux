## 0. Executive summary (ranked by impact)

1. **The new `cleandata` path does not yet do what it is meant to do; three of its assumptions are false on real generator output.**
   - `uniform_remeshing.py` (`process_uniform_dataset`) builds the *parent tube* (`build_parent_tube` → polyball → isotropic remesh). It does not remesh the original vessel. If `uniformly_remeshed/` is filled with it, the training "GT" has **no aneurysm**. A remesh-of-the-original function is needed (`cleaned_io.write_coarse_from_uniform` already has the right shape: `remesh_surface_isotropically` on a given mesh, `PreserveBoundaryEdges=1`).
   - `centerline_creation.py` output has **no `GroupIds`/`Blanking`/`CenterlineIds`/`TractIds`**: `vmtkBranchExtractor` writes them as *cell* data and `clip_centerline_at_profiles` rebuilds the polydata copying only *point* arrays (verified: after clipping, cell arrays = `[]`). `extract_groupid_tracts` therefore silently falls back to `extract_unique_tracts` → the legacy overlapping-tract behaviour (2 tracts, 90 % overlap, 0 junctions on SNF00000100).
   - Even with the arrays present, `extract_groupid_tracts` is wrong on real data: `_longest_unique_polyline` re-runs `extract_unique_tracts(snap=0.05)` on near-coincident copies and fragments them — on SNF00000100 the 88.8 mm parent came back as a **4.9 mm stub** (17 % of centerline points covered, 23 mm max gap); and dropping `Blanking==1` runs leaves 1.5–2.1 mm gaps at every bifurcation, above `GROUPID_ENDPOINT_SNAP_MM = 1.0`, so **no junction is ever found**. A three-line rule (longest copy per GroupId, blanked run attached to the daughter that follows it, cell arrays preserved) gives 3 tracts, 1 junction, 100 % coverage, 0 overlap on the same file (§2.3).
   - `template_mesh`, `template_centerline` and `coarse_remeshed` are **required to exist but never read**: `_build_data` still calls `build_scaffold(centerline, vessel)` and builds the constant 2 mm, 40/250/1000-ring Bishop tube. MISR is on the centerline and unused. All 53 smoke tests pass because they use synthetic point-data arrays with exactly coincident copies; none touches a real VMTK file.
2. **The template migration is still entirely ahead and is a scaffold-layer redesign, not a small change.** The decoder's hierarchy, bilinear upsampling, spline pseudo-coordinates, `r*` grid statistics and radial clamp assume the regular (u, θ) grid; the templates are irregular meshes with 2.3 k–34 k vertices, 2–6 open ends and only a `Normals` array. §9 gives the concrete design that keeps the centerline-intrinsic idea and maps each `cleandata` folder to a role.
3. **The decoder's compute is 97 % SplineConv with a 5×5×5 kernel on 128 channels at 64 k nodes** (4.3 s/sample on the 3080 Ti, 24.8 M of 43.4 M parameters), and half of it is wasted: `e_kind` only takes two values on a 5-knot axis, and `Δθ` is normalised by π so ring neighbours map to 0.5 ± 0.016 — the θ axis of the kernel is effectively blind. Fixing the normalisation is a correctness fix; fixing the kernel and channel width frees the compute for what matters (more steps, depth, k-fold sweeps).
4. **The VAE is an autoencoder with a 12 288-dim latent for ~170 shapes** (`LAMBDA_KL = 5e-4`, KL ≈ 0.5 % of the loss). For a Stage 1 that emits tokens along the whole centerline, the recommendation is a *light per-token KL with free bits* on tokens at fixed 2 mm arc spacing, 16–32 dims each (§4.3–4.4). Healthy-segment tokens then collapse to the prior — desired, because the template explains them — and the sac occupies 3–8 informative tokens.
5. **Training hygiene**: no augmentation, no resume, no per-epoch logging, EMA horizon ≈ 47 epochs (early `best.pt` is chosen on near-initial weights), `cuda:1` hard-coded, 4.3 k optimizer steps total. With unlimited wall-time the fix is not speed but: many more steps, mirror augmentation, 5-fold CV, and mm-unit metrics with mesh-validity checks.

Good and worth keeping: the centerline-intrinsic design (Bishop-frame displacements, (u, θ) Fourier conditioning, tree-valued latent), the decoupled radial/shear head with identity init and radial clamp, multi-scale Chamfer with point-to-plane Huber, the cache/warm-up infrastructure and rawdata guard, FP32/TF32, the smoke-test culture.

## 1. What the pipeline does today (as built, commit `7d18f71`)

```
cleandata/uniformly_remeshed/{id}.vtp  (GT)          cleandata/original_centerline/{id}.vtp
cleandata/template_mesh, template_centerline, coarse_remeshed   ← required to exist, NOT read
   └─ dataset.py: extract_groupid_tracts (→ falls back to extract_unique_tracts on real files)
      → _orient_tracts / canonical pose → allocate rings (40/250/1000 total)
      → Bishop frames → 3 tube scaffolds (R = TUBE_RADIUS_MM = 2.0, 6/12/64 radial)   ← MISR unused
      → couple_ostium_edges (k = 2 NN within 4 mm of ostia)
      → x_true: 16 384 GT points (75 % FPS + 25 % far-from-centerline) + GT normals
      → raycast.py: r* along Bishop normals (Voronoi + 4 mm ambiguity guard)
      → 96 latent token slots (tract-proportional + junction tokens), attend masks
      → one 16 MB .pt per sample (CACHE_VERSION = 8)

model.py   Encoder  PointNeXt: stem(xyz) → SA 16384→1024→256→64→64 (r = 1.5/3/6/12 mm), InvRes blocks
                    → CenterlineLatentHead: 96 positional queries → μ, logσ² (128)
           Latent   reparam → LatentTractSelfAttention (window ±2, ALiBi, gated)
           Decoder  per level: LatentCrossAttention (γ(u), γ(θ) queries → z tokens, tract-masked)
                    + coarse-only positional self-attention
                    + 4 × ResidualSplineConv(128, kernel 5³, degree 2, aggr add, no norm)
                    + DecoupledDisplacementHead → Δr = softplus − R, Δs = 3·tanh (Bishop frame)
                    coarse → bilinear (u,θ) upsample → mid → upsample → fine (64 000 nodes)

losses.py  recon = Σ_levels w_l · weighted Chamfer (pt-to-plane Huber δ = 1 mm + 0.2 L2, weights 1 + d_cl/R ≤ 4)
           + λ_kl·KL (annealed 20 ep) + 0.15·Dirichlet(Δr,Δs) + 0.05·Laplacian + 0.02·normal consistency
           + 1.0·radial Huber(r_pred vs r*) on valid nodes

train.py   AdamW 2e-4, wd 1e-4, cosine 200 ep, bs 1 × accum 8, clip 1.0, EMA 0.999, val every 5 ep (EMA), random 85/15 split
```

Relation to the whiteboard: Stage 2 = "PointNeXt → x0; SplineConv decoder conditioned from the latent (FiLM/AdaIN); train with `z ~ N(x0, I)`, infer with `z = x0`". The implementation uses per-level cross-attention instead of FiLM (more expressive, fine) and a learned-σ VAE instead of fixed unit noise (see §4).

### 2.3 `extract_groupid_tracts` on real data (`probe_groupid_tracts.py`)

| input | result |
|---|---|
| clipped file (what `centerline_creation.py` writes) | no arrays → fallback → 2 tracts of 95.8 / 95.0 mm, **90 % mutual overlap, 0 junctions** (legacy behaviour) |
| unclipped file with cell arrays (what the code's `_cell_data_array` branch expects) | 3 tracts of **4.9** / 11.8 / 11.3 mm, 0 junctions; parent collapsed from 88.8 mm to a stub; 17 % of centerline points within 0.3 mm of a kept tract; max gap 23 mm |

Two independent defects:
- `_longest_unique_polyline` collapses duplicates with `extract_unique_tracts(snap=0.05)`. Real copies differ by 0–0.05 mm point-to-point, so some points snap and others don't; the merged graph acquires spurious junctions and fragments; `max(tracts, key=_arc_len)` then returns the longest *fragment*. Taking the longest *copy* directly (each copy already spans the whole group) is both simpler and correct.
- Dropping `Blanking==1` runs removes the bifurcation segment, so the parent end and the daughter starts are 1.5–2.1 mm apart (≈ one parent radius, not "~1 MISR apart" as the comment assumes for a 1 mm snap). No junction → `_choose_inlet` picks arbitrarily (tract 1 = a daughter, in the test above) → the canonical pose is arbitrary too.

Validated rule (`prototype_branch_tracts.py`, scratch only): per `CenterlineId`, order cells by `TractId`; prepend each blanked run to the non-blanked run that follows it; keep the longest copy per `GroupId`; snap endpoints at 1 mm. Result on the same file: tracts 88.8 / 13.3 / 12.9 mm, junctions `[1]`, 100 % of centerline points within 0.3 mm of a kept tract (max gap 0.17 mm), pairwise overlap ≤ 1 %. The parent keeps its GroupId identity, daughters start where the parent ends, and the bifurcation region is covered exactly once per daughter (they overlap only inside the ~1.6 mm blanked zone, which is where the two daughter tubes have to merge anyway).

Also: the silent fallback to `extract_unique_tracts` should become an error for `cleandata` inputs (they are guaranteed to come from `centerline_creation.py`); keep the fallback only for the synthetic tests.

### 2.4 Findings from the legacy cache that carry over

These were measured on the v7 `rawdata` cache (172/28 split, 200 ICA samples) and remain relevant because the same scaffold code is still in use:

- **Coincident tracts poison everything downstream** (legacy: median 75 % of scaffold points on top of another tract; 89/200 samples with tracts but no junctions; 0/200 clean): `r*` valid on only ~40 % of fine nodes because `voronoi_ok_hit` rejects hits owned by a coincident tract; `couple_ostium_edges` explodes (up to 172 k cross-tract edges out of 362 k) and, with `aggr="add"`, makes junction nodes 10× hotter; tokens are wasted on 2-ring degenerate tracts; the output is self-overlapping by construction. §2.3 fixes the cause; the same numbers will reappear if the fallback path is what runs.
- **Short centerlines** (legacy: 94/200 UPF/USFD/ANSYS cases covering only the aneurysm neighbourhood, 20–60 % of the vessel > 5 mm from the scaffold) are fixed *by construction* by re-extracting centerlines inlet→all outlets on the original vessel — provided `measure_open_profiles` finds every opening. `1or0.py` / `hascap.csv` is exactly the curation this needs; keep its discard list as a cache-time exclusion.
- **Constant 2 mm radius** (§2.2: MISR 0.9–2.75 mm on one vessel): daughter branches sit near the `softplus − R` floor; the identity init is only right for the ICA trunk. Templates fix this; until then `TUBE_RADIUS_MM` should at least become the per-tract median MISR.
- **Fixed 1000 fine rings** regardless of length → ring spacing 0.01–0.3 mm across samples, so the decoder's physical receptive field varies by an order of magnitude (Δu is normalised per tract by the ring step). Fixed physical spacing — which an isotropic remesh gives you — is preferable.
- **`r*` semantics**: rays that leave through the neck and miss, or graze at `normal·ray < 0.2`, are `valid=False, ambiguous=False` and keep Dirichlet weight 1; only double hits unlock it. So the smoothness prior is stiffest on part of the neck where the wall must change fastest. Drive the weight from the GT (distance of the nearest GT point from the centerline / template) rather than from ray-cast success.
- **Voronoi centerlines bend into large sacs** (paths minimise ∫1/R). Template→GT max distances of 1–6 mm on the 95 templates are consistent with the template bulging under the sac. Consequences: less residual for Stage 2 (fine), but the centerline leaks sac position/size, which Stage 1 must then reproduce. Add a cache-time diagnostic (deviation of the centerline from a spline through the healthy segments either side of the sac; MISR cap hit rate). Since manual work is acceptable: if the deviation is common, build templates from `hemoMesh --removal` aneurysm-removed vessels (point-picking tool exists in the repo) so that "centerline = healthy parent" holds for both stages.
- **The only checkpoint ever written** (`output/last.pt`, epoch 1) has epoch-mean train recon 15.5 mm² vs 0.6 mm² for an *untrained* model on a clean long-centerline sample: the uncovered-vessel group dominated the loss. No loss weight in `config.py` has ever been validated at convergence.

## 3. Encoder (PointNeXt)

Parameters 18.5 M (16.8 M InvRes blocks, 12.6 M of that in stage 3 with 512×4 expansion; 1.2 M latent head; stem 192). Fast (64 ms forward on 16 k points). mm-scale radii (1.5/3/6/12 mm) are sensible; canonical pose removes the need for rotation invariance.

1. **Raw xyz only.** GT normals are cached but not fed. Concatenate normals (and, once the template exists, the signed distance to the template) at the stem.
2. **The latent head is a single-head, single-layer, positional-query cross-attention** from 96 queries (γ(u) + tract embedding, no content) to the 64 stage-4 (12 mm) tokens; no FFN, no LayerNorm, no multi-head, no access to stage-2/3 features that hold sac-scale detail. Angular information ("which side of the ICA") can reach a token only through content, so this is where capacity is needed. Replace with a local-pooling transformer head (§4.4).
3. **Capacity misallocated**: 12.6 M in stage 3 (64 points) vs 1.2 M in the head. Halve stage-3 width, move capacity to the head.
4. `logvar.clamp(-8, 2)` kills gradients outside the range; with the tiny β the floor is reached.

## 4. Latent space and VAE

### 4.1 As built

96 tokens × 128 = 12 288 dims. `LAMBDA_KL = 5e-4` on a KL summed over 128 dims and averaged over tokens (≈ 15 nats/token at init → 0.007 in the loss vs recon 0.6): the KL never exceeds ~1 % of the objective, σ goes to the clamp floor, and the model is an autoencoder with an unsmooth, unscaled latent. Tokens are `linspace(0,1)` per tract plus junction tokens at `u = 1.0` (sharing their positional key with every incident tract's last token). `LatentTractSelfAttention` (window ±2, gated) is fine.

### 4.2 What Stage 1 needs from the latent

Stage 1 will emit, per centerline sample, `[x, y, z, r, z_1 … z_D]` along the whole tree (the whiteboard's `x, y, z, r, c` row). The latent is therefore a **tree-structured sequence of local tokens**, and Stage 1 is a conditional sequence generator over it. Requirements: fixed per-dimension scale; smoothness (Stage 1 lands *near* training codes); decoder robustness to Stage 1 error; and, ideally, a known null code for healthy segments so Stage 1 only has to model where the sac is.

### 4.3 VAE vs AE + noise — trade-off and recommendation

| | β-VAE (meaningful β) | AE + fixed-σ noise + standardisation | **Light per-token KL-VAE with free bits (recommended)** |
|---|---|---|---|
| Reconstruction accuracy | Costs accuracy; the trade-off is steep on ~170 samples | Maximal | Near-AE: the free-bits floor means KL only bites on unused dims |
| Latent scale | Unit by construction | Must be standardised explicitly; σ in those units | Near-unit; a final standardisation pass is cheap insurance |
| Healthy segments | Collapse to the prior — *desired* here (template explains them) | No pressure toward a null code; Stage 1 must model arbitrary codes | Same desirable collapse; per-token KL along the centerline becomes a diagnostic of where the template fails |
| Robustness to Stage 1 error | Built in | Built in, σ directly controls it | Built in at the learned posterior width; add a small extra noise term if it narrows too much |
| Prior sampling without Stage 1 | Yes (sanity check) | No | For healthy tokens yes; full shapes not meaningful |
| Diagnostics | Active units | None | Active units + per-token KL profile |
| Failure mode | Global collapse → blurry sacs | Wasteful latent; σ mis-set → brittle or blurry | Two knobs, wide safe range |
| Whiteboard | — | Matches `z ~ N(x0, I)` after standardisation | Same with learned noise level |

Recommendation: third column. Per-token KL to N(0, I), free-bits floor ≈ 0.1–0.25 nats/dim, β such that total KL is ~2–5 % of recon at convergence (start ~1e-2 on a per-dim-averaged KL), keep the 20-epoch warm-up. Log three things: active units (healthy vs sac tokens), the per-token KL profile along the centerline, and a **noise-robustness curve** (recon when decoding μ + σ·ε for σ ∈ {0, 0.25, 0.5, 1} standardised) — the interface contract with Stage 1. Fall back to AE + fixed σ ≈ 0.2–0.3 only if β proves untunable. Once Stage 1 exists, fine-tune the decoder on Stage 1 samples (teacher-forced centerline, generated tokens).

### 4.4 Token geometry, and why 2 mm

Token spacing `ds_tok` sets (i) the smallest wall feature one token must encode alone, (ii) how many tokens the sac spans, (iii) Stage 1's sequence length. Anatomy: ICA segment + branches ≈ 80–130 mm of centerline; neck 3–6 mm; sac height 3–15 mm.

| `ds_tok` | tokens / sample | tokens on a sac | token width needed | remarks |
|---|---|---|---|---|
| 1 mm | 80–130 | 5–15 | 8–16 | very local; long Stage 1 sequence (fine for a transformer); tokens finer than the template's own ~0.4 mm edge scale buys little |
| **2 mm** | **40–70** | **3–8** | **16–32** | neck / body / dome fall on different tokens; total latent 1–2 k dims; comfortable sequence length |
| 3–4 mm | 25–40 | 1–4 | 32–64 | a sac becomes one or two "blob" tokens; angular detail must be packed into width — the current design's problem in miniature |
| adaptive (denser where the wall deviates) | — | — | — | rejected: token positions must be a function of the centerline alone so Stage 1 can place them without knowing the sac |

Recommendation: `ds_tok = 2 mm`, `D = 32`, defined as one shared constant for both stages; Stage 1 may resample the centerline at 1 mm for geometry and place a texture token on every second sample. Tokens sit on the *original* centerline (the thing Stage 1 generates); no separate ostium tokens — the bifurcation is where two branches' sequences meet, and the tree gives adjacency. The decoder's cross-attention interpolates between the ~5 nearest tokens along the branch (plus the neighbouring branch's tokens near an ostium), so features between tokens remain representable.

Encoder head that produces this: assign each GT point to its nearest centerline sample (Voronoi along the tree), attention-pool PointNeXt features per sample, then 2–4 transformer layers over the token tree with arc-length and branch-depth positional encodings. The latent is then explicitly local, which is the right inductive bias for ~200 samples: each sample contributes 40–70 local examples of "wall residual given local code".

## 5. Decoder

Parameters 24.8 M, of which 24.6 M are the 12 SplineConvs (2.05 M each: 5³ = 125 basis × 128 × 128); cross-attention 3 × 59 k; coarse self-attention 82 k; heads 387 each.

### 5.1 Pseudo-coordinates — one correctness bug, one waste

```56:63:1test_encoder_decoder_only/train_pipeline/geometry.py
    e_u = 0.5 + 0.5 * (du / step).clamp(-1.0, 1.0)
    # ...
    dth = wrap_pi(theta[dst] - theta[src])
    e_th = 0.5 + 0.5 * (dth / math.pi).clamp(-1.0, 1.0)
    # ...
    return torch.stack([e_u, e_th, e_kind], dim=-1)
```

- `e_u` is normalised by the ring step → longitudinal neighbours at 0 / 1 (kernel corners). Correct.
- `e_th` is normalised by π. On the 64-ring fine level the circumferential neighbour has `dth = 2π/64` → `e_th = 0.516`; the (−θ, same, +θ) neighbours land at 0.484 / 0.5 / 0.516, where the degree-2 B-spline basis is nearly identical. The fine conv cannot tell left from right ring neighbour; it is effectively a 1-D filter along u with a symmetric θ blur. Normalise `dth` by the local ring step (or, after the migration, by the physical edge length) so neighbours land on the kernel corners.
- `e_kind` is 0.5 for same-tract and 0 for cross-tract edges: one bit on a 5-knot axis that multiplies parameters and `spline_weighting` FLOPs by 5. Use kernel `(5, 5, 2)` with degree 1 on the last axis (−60 %) or a separate small conv for cross-branch edges and a 2-D kernel for mesh edges (−80 %).

### 5.2 Compute profile (3080 Ti, one sample, 64 000 fine nodes, 383 k directed edges)

| | time |
|---|---|
| full train step (fwd + bwd + AdamW) | **4.28 s / sample**, 2.7 GiB peak |
| `pyg::spline_weighting` fwd / bwd-x / bwd-w | 0.97 / 0.95 / 2.17 s — **97 % of GPU time** |
| encoder forward (eval) | 64 ms |
| decoder forward (eval) | ~1.0 s |
| losses forward (eval) | ~1.0 s (sync-dominated; knn itself 23 ms) |

172 samples ≈ 12 min/epoch → 200 epochs ≈ 41 h on the 3080 Ti, only 4.3 k optimizer steps. The spline kernel is scalar FP32 CUDA (no tensor cores), so an A100 buys ~1.5–2×. Multiplicative levers: kernel 125 → 50/25 basis (2.5–5×), fine channels 128 → 64 (4×), fine nodes 64 k → 12–16 k as the templates naturally provide (4–5×). Any two make a run an overnight job locally; with unlimited wall-time the point is not speed but affording 2–5·10⁴ steps, deeper decoders and k-fold sweeps.

### 5.3 Aggregation and normalisation

```646:657:1test_encoder_decoder_only/train_pipeline/model.py
        kernel_size: int = SPLINE_KERNEL_SIZE,
        # ...
            kernel_size=kernel_size,
            degree=degree,
            aggr="add",
            root_weight=False,
```

`aggr="add"`, `root_weight=False`, no normalisation anywhere in the decoder convs. Degree is 6 on the grid, 50–100 at junctions with the current coupling edges, and 5–8 varying on a template mesh. Use `aggr="mean"` (or degree-normalised sum), pre-LayerNorm/GraphNorm inside `ResidualSplineConv`, `root_weight=True`.

### 5.4 Cross-attention from nodes to latent

Queries purely positional (γ(u), γ(θ)), keys `w_k([z_k, γ(u_k)])`, values `w_v(z_k)`, output `out([a, γu, γθ])`: a content-keyed positional interpolation of the latent along u — sensible. Single head, no FFN; θ enters only through `out`. Two heads + a small FFN cost nothing; more importantly, with 2 mm tokens attention should be restricted to the ~5 nearest tokens along the branch (cheaper and more stable than softmax over a whole tract).

### 5.5 Hierarchy, upsampling, features

`bilinear_cylindrical_upsample` is exact for the grid and is the one component that cannot survive an irregular template (§9). The gated upsampled hidden state, identity-initialised heads and `dx_f = up(dx_m) + local` composition are good. The decoder never sees centerline geometry (curvature, torsion, `R_local`, distance to the nearest ostium) — add them as node features; they are cheap and give a direct handle on "daughter branch vs trunk" and bifurcation geometry.

### 5.6 Displacement head

Δr = softplus(·) − R (floor −R), Δs = 3·tanh. Sized for a 2 mm tube; on bottleneck (overhanging) sacs dome vertices must travel several radii tangentially, which a 3 mm cap makes unreachable. Suggest free 3-D displacement at the coarse level (few vertices, dome placement) and MISR-relative local-frame residuals at mid/fine (floor ≈ −0.8·R_local, shear cap ∝ max(3 mm, k·R_local)).

### 5.7 Output topology

Today: overlapping open tubes at bifurcations (and everywhere, with coincident tracts) — not a manifold, not CFD-usable. With the template as scaffold the output inherits the template's topology (one component, `n_profiles` open loops); see §10 for what keeps it fold-free.

## 6. Losses

- **Chamfer**: both directions, weights `1 + d_cl/R` capped at 4, point-to-plane Huber δ = 1 mm + 0.2 L2, GT normals in both directions — well designed. Gaps: (i) pred side uses vertices, so a stretched dome is under-sampled — sample points on predicted faces (`sample_points_from_meshes`), which is also triangulation-agnostic; (ii) the far-point weighting is right for sacs but rewards uncovered vessel — moot once centerlines cover the vessel (§2.4), until then those samples must be excluded.
- **Radial Huber vs `r*`** (λ = 1): the cleanest signal on the parent; coverage limited by the coincident-tract problem (40 % valid, legacy). With the template, `r*` = `StretchDistance` along the template normal, valid nearly everywhere except under the sac.
- **Dirichlet on (Δr, Δs)** (λ = 0.15, squared per edge): with 0.3 mm rings and a 10 mm sac over a 3 mm neck every neck edge costs ~(1 mm)² unless unlocked by `ambiguous`; §2.4 explains why part of the neck stays locked. Use a robust (Huber/L1) or second-difference penalty and GT-driven weights.
- **Uniform Laplacian on absolute positions** (λ = 0.05) penalises the tube's own curvature including the sac; the *displacement* Laplacian would not. Low priority.
- **Normal consistency** 0.02: fine.
- **KL**: §4.
- **Missing**: triangle stretch / edge-length-ratio regulariser (the actual failure mode on domes) and a normal-flip (fold) penalty — both required for §10.
- Validation score = recon + rad (no smoothness): good for selection, not for reporting (§11).

| item | current | issue / suggestion |
|---|---|---|

| multi-GPU | none | 4 × A100 as 4 independent configs/folds; DDP not worth it at this data size |
| precision | FP32 tensors, TF32 matmuls | correct; spline kernel and knn are FP32 anyway; no AMP |
| checkpointing | off | correct (2.7 GiB peak) |
| data loading | 3 workers, 16 MB `torch.load` per item | fine |

## 8. Spending compute for accuracy, not speed

| lever | expected effect | cost |
|---|---|---|
| full GT point set (15–50 k) + face-sampled predicted points, resampled every epoch | removes the 16 k sampling floor and the dome vertex-density bias | memory only |
| augmentation set of §7 | largest single generalisation gain on ~200 samples | free |
| 5–10× more optimisation steps | training is nowhere near convergence at 4.3 k steps | time, affordable after §5.2 |
| decoder depth (6–8 residual convs/level, pre-norm) and multi-head cross-attention + FFN instead of the 5³ kernel | capacity where it is used | modest after the kernel fix |
| local-pooling transformer latent head (§4.4) | better latent, less overfitting | small |
| normals into the encoder | cheap accuracy | free |
| extra finest level at the template's native resolution | sac detail | VRAM (available) |
| curriculum: radial-only warm-start on the parent, then unlock sac terms | faster, more stable convergence | free |
| 5-fold CV | error bars on every design decision | 5× per config; this is what the A100s are for |
| batch size > 1 | stabilises gradients only | fill VRAM with it, don't optimise for it |

## 9. Migration to the template scaffold (concrete design)

### 9.1 What breaks on an irregular template

| component | assumes | on the template |
|---|---|---|
| `allocate_ring_counts`, `_generate_level`, `branch_nl`/`n_radial` bookkeeping | regular rings × radial grid per tract | no rings; vertex count varies 15× |
| `bilinear_cylindrical_upsample` / `upsample_branch_concat` | source/target grids per branch | no grids |
| `intrinsic_spline_pseudo_coords` | Δu in ring steps, Δθ | needs (branch, u, θ) per vertex — not exported |
| `r_star_grid_stats`, `smoothness_edge_weights` | ring/column neighbours | no rings |
| `radial_bias_for_zero_init`, `clamp_residual_radial`, `DecoupledDisplacementHead` | constant tube R | `R_local` per vertex |
| `_build_latent_tokens` | tracts from `extract_unique_tracts` | branch tree from the cell arrays (§2.3), tokens at 2 mm |
| coarse self-attention masks, `attend` tables | per-tract node ranges | per-vertex branch id from projection |
| `postprocess.tensor_to_vtp` | grid faces | template faces (simpler) |
| Chamfer, radial Huber, normal consistency, Laplacian, encoder | any mesh / point cloud | unchanged |

### 9.2 Design that keeps the centerline-intrinsic idea

1. **Scaffold = `template_mesh`**; per-vertex parametrisation by projecting onto the branch tree built from `original_centerline` (§2.3 rule): `branch_id`, `u` (arc position), `θ` (angle in that branch's Bishop frame), `R_local` (interpolated MISR from `template_centerline` or `compute_template_local_radii`), `r*` = `StretchDistance`. Export these from the generator where they already exist; compute the rest at cache time.
2. **Hierarchy = three isotropic remeshes of the same template** (≈ 1.5 mm coarse, 0.5 mm mid, the variable mesh fine). Inter-level upsampling = barycentric interpolation onto the nearest coarser face (or 3-NN inverse distance), precomputed once per sample as index/weight tensors — a sparse matmul identical for every mesh. This is what `coarse_remeshed` should hold (coarse *templates*), or a sibling folder.
3. **SplineConv stays**, with pseudo-coords `(Δu/ℓ, Δθ·R_local/ℓ, kind)` where ℓ is the level's target edge length — physical normalisation fixes §5.1 and makes kernels scale-consistent across samples. Edges = template triangle edges (+ a few kNN edges across branches near ostia).
4. **Displacement in the template's own frame**: Δr along the template normal (≈ radial from the branch centerline on a MISR tube), Δs in the tangent plane; MISR-relative bounds; free 3-D at the coarse level (§5.6).
5. **Tokens** at 2 mm along the original centerline (§4.4); decoder cross-attention to the nearest tokens along the vertex's branch.
6. **Cache**: full GT vertices + normals; mirror copy as a second sample; interpolation tensors; quality gates of §2.5.
7. **Inference path = Stage 1 centerline → `build_parent_tube` → variable remesh → Stage 2 decode**, i.e. the same generator code runs at inference. Train Stage 2 on templates built from centerlines of the kind Stage 1 can output (smoothed, MISR-capped — already the case), not from anything hand-tuned per sample.

The alternative — dropping (u, θ) for a generic mesh GNN (SplineConv on 3-D offsets, or DiffusionNet) with FiLM/AdaIN from a global latent, as the whiteboard sketches — is simpler to implement but loses the along-centerline latent structure that makes Stage 1 tractable. Keep the intrinsic design.

## 10. Watertight single manifold for CFD

Deforming the template preserves its topology iff the deformation does not fold. Outlet position/planarity will be fixed in post and outlets need not be circular, so the boundary constraint is optional; what remains mandatory:

1. **Fold prevention**: hinge penalty on `n_pred · n_template < 0` per triangle, plus a stretch regulariser (per-triangle singular values or edge-length ratios, ARAP-style). These are the real failure modes of a fixed-topology deformer on overhanging sacs.
2. **Displacement bounds that can reach the dome** (§5.6) — otherwise the network folds the neck trying.
3. **Verification in `postprocess.py`**: self-intersection count (`vtkIntersectionPolyDataFilter` self-intersection mode or pymeshlab), boundary-loop count = `n_profiles`, one connected component, min triangle angle / aspect ratio — reported as validation metrics.
4. **Final isotropic remesh** of the decoded surface (the pipeline's remesher, `PreserveBoundaryEdges`) before CFD; the variable template's dense-under-the-sac sizing means the *deformed* mesh is already roughly uniform, which is what the `k = 1 + d/R` sizing was for.
5. Optional and cheap: keep boundary-loop vertices in their profile plane during training (project Δ onto the plane); it stabilises the ends and costs nothing since the GT was clipped on the same planes.
